# Evaluation

How well Rekindle finds connections, measured against one person's labels. The harness and how to run it are in [`evals/README.md`](../evals/README.md); every table it produces is in [`evals/REPORT.md`](../evals/REPORT.md).

## Models

`pnpm eval` runs Rekindle's real retrieval and triage against articles and projects labeled by a person (see [`evals/README.md`](../evals/README.md)); the full tables are in [`evals/REPORT.md`](../evals/REPORT.md). Latest runs (the 3 closest projects per article reach the LLM). The default uses the current prompt, which since 2026-10-21 shows every note of the project and asks for structured suggestion text (both below); Qwen, marked †, was measured with the notes prompt before the structured text, and Gemini and thinking on, marked \*, with the prompt of 2026-10-19; none of those was repeated: one labeler (the project owner), 47 articles × 8 projects = 376 labeled pairs (35 actionable, 21 tentative, 320 irrelevant), each provider alone with no fallback, identical summaries and retrieval:

**Structured suggestion text (2026-10-21).** The answer now gives an action as a one-sentence headline and 1 to 4 steps (note, place, change, text to paste), and its reasoning as the connection first and then what is missing, so the card and the callout can lay them out. The prompt just before it scored macro-F1 0.75 and 0.72 in two runs (45 and 44 connections, `actionable` 96% / 77% and 96% / 71%, 0 invalid answers); the structured one 0.69, 42 connections, 92% / 63%, and 9 answers that were not valid JSON (2 pairs lost after the retry; in the app the next provider takes over). The same prompt run twice changes 11 or 12 of the 118 verdicts, always to or from `tentative`, so part of this gap is run-to-run variance; the structured prompt changed 17. Getting the structure from a second call left the verdicts untouched but costs about one extra call per actionable or tentative answer; the owner chose one call. Estimated cost depends on the hour of the run and is not comparable between these runs.

**The notes prompt (2026-10-21).** Until then the model saw the path of one note (the one closest to the article) and every other note by title only, cut to 15,000 characters in file order, so every suggestion pointed at the closest note (27 of 27 in the run with the previous prompt). Now every note's path is listed, notes are sent whole up to 60,000 characters per project (closest first when a project is larger), and the model may point at any note or propose a new one. With the previous prompt the default scored macro-F1 0.77, `actionable` 100% / 77% and 46 connections with 19 extra, at 2,170 input tokens per call and an estimated $0.024; with the current one 10 of its 28 actions point at a note other than the closest, and none proposed a new note. Most labeled projects have 1 to 4 notes, so this dataset says little about note choice in a large project, and whether the chosen note is the right one is **not measured**.

*Generated by `pnpm eval chart` from the result files in `evals/results/`.*

**Connections found** treats `actionable` and `tentative` as one answer, "this article connects to this project": calling an actionable pair tentative, or the reverse, still shows you the connection, so only a lost connection or an extra one counts against the model. 7 of the 56 labeled connections never reach the model because of the top-3 cutoff, so 49 is the most any model can find here; *extra* counts pairs labeled irrelevant that the model called actionable or tentative. Relevance is partly subjective: an extra connection may be forced, or it may be one the labeler missed (7 labels were changed for that reason, below), so the aim is actionable connections that are not forced, not zero extras.

DeepSeek with thinking off has the best macro-F1 and is the default (`deepseek,gemini,ollama`, thinking off); it also led when every project within the distance threshold reached the LLM and with the earlier prompts and labels (macro-F1 0.74 vs 0.56 and 0.61, in [`JOURNEY.md`](JOURNEY.md)). Thinking on trades the other way: it finds every connection that reaches it and 4 more actionable pairs, but proposes 7 more extra connections, calls 8 pairs actionable that are not, and takes nearly twice the latency and more than twice the output tokens. Gemini behaves like thinking on, with more false actionables.

**The labels were revised after seeing these answers.** On 2026-10-19 the owner read the pairs thinking on called actionable and changed 7 labels, every one toward thinking on's answer (2 tentative → actionable, 2 irrelevant → actionable, 3 irrelevant → tentative). All the numbers in this section use the revised labels, rescored from the recorded answers with `pnpm eval rescore` (no new model calls); this favors thinking on. Before the revision thinking on scored macro-F1 0.69 against 0.78.

Recall counts the relevant pairs that the top-3 cutoff never sends to the LLM as misses. These numbers come from a small, single-labeler dataset: treat gaps of a few points as noise. Run-to-run variance is measured only by two repeats: repeating the thinking-off run on 2026-10-19 gave macro-F1 0.75 against 0.77, 25 actionable pairs found instead of 27 with 1 false actionable instead of 0, and 47 connections instead of 46 (11 of 118 verdicts differed); repeating the notes prompt on 2026-10-21 gave 0.72 against 0.75 (12 of 118 differed). Retrieval at the 0.6 distance threshold finds 91% of the relevant projects but lets 94% of unrelated articles through (precision@3 59%). Suggestion quality (usefulness, actionability) is **not measured**.

**Tokens and cost.** The thinking-off token and cost figures come from the run with the current prompt (with the previous prompt: 2,170 input tokens per call, 1,976 cached, $0.024 for the 118 calls, from the 2026-10-19 repeat run, because the first run did not record cache hits). The current prompt carries every note, so it sends about 75% more input per call; 86% of it was served from DeepSeek's cache, because the notes block is the same for every article. Cost is estimated from the tokens DeepSeek reports and its list prices: cached input costs 2% of uncached input, and both runs were off-peak (half price). Before 2026-10-19 the harness priced every token as uncached and peak-hour, so it overstated cost: its estimates for the DeepSeek runs up to then add up to $0.69, while DeepSeek billed $0.25 for all use up to then (the first run, estimated at $0.18, was billed $0.07; figures from the owner's DeepSeek dashboard, not reproducible from this repo). The new estimates have **not** been checked against the bill yet.

**Real-user testing: not measured.** No session with other people has been run.

## Languages

The language of the model's **instructions** is not a setting: it stays Spanish because that measured best. Measured on the labeled evaluation set (DeepSeek Flash, the 3 closest projects per article, the same 47 articles and 376 labeled pairs as below, with the labels as revised on 2026-10-19; one run each; a repeat of the baseline and the label revision are described above):

| Change from the Spanish baseline | Triage macro-F1 | `actionable` precision / found | Connections found / extra | Retrieval recall@3 / unrelated articles that still retrieve a project |
|---|---|---|---|---|
| Baseline: Spanish instructions, summaries and output | 0.77 | 100% / 27 of 35 | 46 of 56 / 19 | 91% / 94% |
| E1: English output | 0.75 | 100% / 27 of 35 | 45 of 56 / 20 | 91% / 94% (same summaries) |
| E2: English summaries compared with the Spanish notes | 0.71 | 96% / 24 of 35 | 42 of 56 / 25 | 84% / 82% |
| E3: English instructions | 0.72 | 100% / 22 of 35 | 43 of 56 / 10 | 91% / 94% (same summaries) |

What this supports: English output costs nothing measurable (the actionable verdicts were identical), so it is safe to offer. English instructions made the model more reluctant to call an article actionable, so instructions stay Spanish. Summaries in a different language from the notes lose relevant matches (and also filter more, since cross-language distances are larger), so summaries follow the notes. These are single runs on one person's labels; the English-output and English-notes combinations other than these three were **not measured**, and an English vault with English labels was **not measured**. Full tables: [`evals/REPORT.md`](../evals/REPORT.md).
